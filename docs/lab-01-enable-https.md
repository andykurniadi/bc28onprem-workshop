# Lab 1: Enable HTTPS for the Business Central web client

## Goal

Expose the Business Central web client through HTTPS so the OAuth redirect URI is secure and matches the Entra application registration.

## 1. Create a self-signed certificate

On the Business Central server, open an elevated PowerShell session:

```powershell
.\scripts\lab-01-create-certificate.ps1 -DnsName 'win22-bc28'
```

The DNS name must match the hostname users browse to. Record the certificate thumbprint.

## 2. Give the hosting identity private-key access

Open `mmc.exe`, add **Certificates** for **Computer account** and select **Local Computer**. Under **Personal > Certificates**, locate the new certificate. Choose **All Tasks > Manage Private Keys** and grant access to the account used by the Business Central/IIS application pool, such as `NETWORK SERVICE` or the configured service account.

## 3. Add an IIS HTTPS binding

In IIS Manager, select the site hosting the `BC280` web client:

- Add an `https` binding.
- Use port `443` (or `8443` if required).
- Set host name to `win22-bc28`.
- Select the certificate created in step 1.

## 4. Set the public web URL

Run from the Business Central Administration Shell:

```powershell
.\scripts\lab-01-set-public-web-base-url.ps1 `
  -ServerInstance 'BC280' `
  -PublicWebBaseUrl 'https://win22-bc28:443/BC280/'
```

`PublicWebBaseUrl` controls the OAuth landing URL generated by Business Central. It must use HTTPS and agree with the redirect URI registered in Entra ID.

## 5. Trust the certificate on client devices

Export only the public certificate and import it under **Trusted Root Certification Authorities** on each client that accesses the web client. Never export or distribute the private key.

## Validate

Browse to the configured HTTPS URL and confirm the browser reports a trusted certificate. Confirm the setting with:

```powershell
Get-NAVServerConfiguration -ServerInstance BC280 -KeyName PublicWebBaseUrl
```
